# Frontend Architecture Rules

These rules must be strictly adhered to when generating or modifying code in the `frontend/` directory.

## 1. Next.js App Router (Server Components Default)
*   **Always use Server Components by default.** 
*   Do NOT add `"use client"` unless the component requires interactivity (e.g., uses `useState`, `useEffect`, `onClick`, or browser APIs).
*   If a component needs client-side state, try to isolate the stateful part into a smaller leaf component to keep the parent as a Server Component.

## 2. Data Fetching
*   **Prohibited**: Never use `useEffect` for data fetching.
*   **Allowed**: Fetch data directly in Server Components using native `fetch()` or `openapi-fetch`.
*   **Mutations**: Use **Server Actions** for form submissions and data mutations.

## 3. Styling (Tailwind CSS)
*   Use Tailwind utility classes exclusively for styling.
*   Group classes logically (layout -> spacing -> typography -> colors -> interactivity).

## 4. API Consumption
*   Always use `openapi-fetch` to communicate with the Django backend.
*   Rely on the autogenerated TypeScript types (`paths`, `components`) from the backend schema to ensure end-to-end type safety. Do not write manual TS interfaces for API responses.
